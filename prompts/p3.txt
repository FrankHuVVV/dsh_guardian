这是 DSH 完整插件运行环境快照与恢复器 v5【第 3 步：内容寻址 store + exact 快照/恢复】。承接第 2 步已通过。

要做的事：
1. 读取 AGENTS.md 第 2.4 节（硬链接存储模型）、第 3.3 节（exact restore）、第 3 节中 snapshot/list/restore 契约。
2. 实现 `_store` 内容寻址写入：文件内容 → sha256 → _store/<前2位>/<sha256>；不存在则复制进去（复制，不链接 live 文件），已存在则跳过；blob 设为只读。
3. 实现 `snapshot <label>`：只写 meta.json（format=5, mode=exact, storage=content-addressed-hardlink），entries 记录 kind/size/sha256 或 kind/target 或 kind/listingSha256；写 digest。
4. 实现 `restore <label>`：严格按 3.3 的 11 步——校验 meta/digest/blob、校验客户端 asar 哈希（blockOnClientMismatch=true 时不符退出 3）、停客户端、pre-restore 快照、集合差清理（只删本 profile 且 before 中不存在的条目，永不删 _store/shared/external/其他 profile）、物化（文件临时名→rename；symlink/junction 先删再建并校验 target）、重新 discover 后 digest 必须等于 meta.digest、offline preflight、启动验证。
5. 实现 `list`：快照与事务列表，含 LKG 标记。
6. 所有操作写 logs/guardian-YYYYMMDD.log。

完成后逐条执行验收标准：
1) 连续两次 snapshot，第二次 _store 新增字节数 < 5MB（无新插件时接近 0）。
2) 修改 profileDir/package.json、pnpm-lock.yaml、以及 link 目标目录中一个文件后，restore 到快照：三者全部还原，runtime-inventory digest 等于快照 digest。
3) 恢复过程不联网（断网后 restore 仍成功）。
4) 篡改 _store 中一个 blob 后 restore：被拒绝，退出码非 0，不覆盖现场。
5) restore 不删除 _store 中未被引用但被其他快照引用的 blob；不删除 sharedDependencyRoots。
